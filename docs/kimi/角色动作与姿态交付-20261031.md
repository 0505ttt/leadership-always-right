## 3. 可接入接口

### 创建与诊断

```ts
import {
  createCharacterMotion,
  type CharacterMotionInput,
} from './presentation/character-motion';

const motion = createCharacterMotion(visual, { useInternalChair: true });
motion.update(input);
const diagnostics = motion.getDiagnostics();
motion.reset();
```

也可用 `createCharacterMotionUpdater(visual, options)` 取得单一更新函数。`CharacterMotionInput` 继承既有 `CharacterPoseInput`，新增可选字段：

| 字段 | 单位／取值 | 表现层用途 |
| --- | --- | --- |
| `workStance` | `'seated' \| 'chair-standing'` | 原坐姿与椅上站立办公的语义切换 |
| `deskHeight` | 世界坐标 Y，米 | 手腕目标高度；默认沿用上值，初始 1.9 |
| `deskFrontZ` | 角色根局部 +Z，米 | 上下椅时避开桌面前缘；默认 0.365 |
| `speed` | m/s，接入侧实测水平速度 | 只匹配步频，不移动角色根 |
| `lookYawOffset` | 相对角色根的有符号弧度 | 扫视，钳制到 ±π/2 |
| `leaderMode` | `'patrol' \| 'inspect' \| 'search' \| 'chase' \| 'alert'` | 领导表现状态；chase 复用搜查，alert 复用检查 |

`getDiagnostics()` 返回：

- `activity`：`inherited`、`chair-mount`、`chair-work`、`chair-dismount`、`chair-recover`、`leader-patrol`、`leader-inspect`、`leader-search`。
- `support`、`cadence`、`transitionProgress`、`requestedLookYaw`、`appliedLookYaw`、`chairVisible`。
- 左右 `feet`：位置、目标、欧氏误差和 `verticalError`；左右 `hands`：手腕位置、目标和误差。
- 手腕／脚踝目标是骨骼接口，**不等于真实蒙皮接触**；本批预览另行报告 `soles` 与 `handSurfaces`。

### 员工／同事输入示例

```ts
// 进入升高工位；time 是表现时钟，不是玩法计时器。
motion.update({
  pose: 'working', workStance: 'chair-standing',
  deskHeight: 1.9, deskFrontZ: .365,
  moving: false, sprint: false, holding: false, pot: 'none', time,
});

// 下椅并恢复原坐姿；低桌由接入侧按真实状态提供。
motion.update({
  pose: 'working', workStance: 'seated', deskHeight: .75,
  moving: false, sprint: false, holding: false, pot: 'none', time,
});

// 或离椅恢复站立。
motion.update({
  pose: 'standing', workStance: 'seated',
  moving: false, sprint: false, holding: false, pot: 'none', time,
});
```

`visual.root` 的世界位置和朝向仍由接入侧提供。本模块只求骨骼姿态、保持挂点并调整内部椅子的局部表现偏移；不会把权威控制根升到椅面，也不会实现角色的上椅移动、碰撞或交互判定。内部椅与场景正式椅的去重仍由 Codex 按真实工位处理。

### 领导输入示例

```ts
motion.update({
  pose: 'standing', leaderMode: 'search',
  moving: true, sprint: true, speed: 7.2,
  lookYawOffset: Math.PI / 2,
  holding: false, pot: 'none', time,
});
```

- 巡逻使用正式 `walk`；搜查使用正式 `run`，`7.2 / 4.8 = 1.5×` 步频。
- 停步检查混合时间 **0.18 s**；其他领导模式切换为 **0.14 s**。
- 扫视由 Spine2／Neck／Head 分别承担 **35%／30%／35%**，总范围左右各 90°；不旋转权威根。
- `back`、`crown`、`pelvis` 挂点在对应骨骼局部坐标中保持，专项测试验证左右扫视前后偏移小于 `1e-7`。
- 7.2 m/s 是初始表现参考，不在本模块产生位移、视野、发现、追踪或抓捕。

## 4. 尺寸、接触和过渡参数

| 项目 | 当前值／约定 |
| --- | --- |
| 正式椅座面 | `seatY = 0.5475365868050991 m`，`seatProbeZ = 0.160 m` |
| 脚踝目标 | 座面以上 `0.105 m`；左右 X 为 `±0.13 m`，前后 Z 为 `0.10 / -0.02 m` |
| 上椅 | `0.78 s`；左脚支撑段 `0…0.62`，右脚 `0.38…1`，形成错峰 |
| 下椅／恢复坐姿 | 均 `0.56 s`，支撑权重归零后回到原 standing／working 路径 |
| 手腕最终目标 | 桌面以上 `0.085 m`，X `±0.20 m`，根局部前伸 `0.50 m` |
| 桌面安全接近 | 桌前缘默认 `0.365 m`；过渡时手腕先在前缘后侧 `0.23 m`，高于桌板后再前伸 |
| 下椅手部路径 | 先在桌板上方收回，再下降；接近原坐姿时平滑恢复原手部 Z |
| 真实手部验收阈值 | 桌面投影内蒙皮最低点相对桌面 `-0.006…+0.012 m` |
| 真实脚底验收阈值 | 相对座面 `±0.025 m`，同时检查脚踝目标误差 |
| 员工／同事正式材质 | 保留 `MeshStandardMaterial`；每人一把内部正式椅 |
| 坐标 | +Y 向上、角色前方 +Z；报告中的接触与组合最高点为世界坐标 |

`deskFrontZ` 是新增的可选表现绑定，不要求 Codex 改共享状态。真实工位尺寸不同则由接入侧换算到角色根局部坐标；不能只绑定桌高而忽略前缘。

## 5. 最终实测证据

### 数值结果

以下员工与同事在独立预览中使用同一正式员工表现资产，结果一致：

- 真实手部蒙皮最低点：左 **+1.850 mm**、右 **−0.298 mm**，相对 1.90 m 桌面；允许范围为 −6…+12 mm。
- 真实脚底相对座面：左 **−0.538 mm**、右 **+3.855 mm**。
- 椅上员工真实蒙皮最高点：**2.277269 m**。
- 生产 `back` 挂点上的锅体最高点：**1.846823 m**；人物＋锅组合最高点仍为 **2.277269 m**，低于预览参考面 **2.35 m**。该参考面不是主场景顶板或碰撞验收。
- 领导左右扫视实测应用角度分别为 **+90°／−90°**，搜查步频 **1.5×**。

### 自动检查与实看

- `npx vitest run tests/character-motion.test.ts`：**8／8** 通过。
- 最终 `npm test`：**20 个测试文件、276 项测试全部通过**。
- 最终 `npm run build`：TypeScript 与 Vite 构建成功，60 个模块完成转换；仅有现存大 chunk 提示。
- `node scripts/capture-character-motion.mjs`：**18 张** 1440×900 PNG、**31 个**过渡采样；`errors=[]`、`contractFailures=[]`。
- 新增过渡检查覆盖手部接近／离开桌板；曾实际发现上椅中段手部跨桌板问题并修正，最终采样无同类阈值失败。
- 两张联系图覆盖全部 18 个画面，已实际查看；另放大检查升高办公正面、侧面、恢复和背锅细节。未见明显椅背穿人、最终手部抬离桌面、背锅悬浮或领导不合理扭头。冻结帧不冒充整局连续操作通过。
- 报告 `sourcesUnchanged=true`，正式模型及本批源文件在截图期间哈希一致；`ownedServerStopped=true`、`portReleased=true`，没有留下本脚本启动的开发服务。
- 浏览器警告保留：Three.js 阴影 API 弃用、ReadPixels GPU stall、软件 WebGL 不支持 KHR_parallel_shader_compile；没有控制台或资源加载错误。

### 性能影响

最新浏览器微基准对每种角色调用 `motion.update` 180 次：

| 角色 | 总耗时 | 单次平均 |
| --- | ---: | ---: |
| 员工椅上办公 | 498.2 ms | **2.768 ms** |
| 领导搜查 | 422.5 ms | **2.347 ms** |

仅表示该环境下单次动作求解的浏览器 CPU 微基准，**不含渲染、蒙皮上传、GPU、FPS、九角色整局、主场景碰撞或真实领导追踪成本**，不能据此宣称整局流畅。

升高工位包含支撑过渡和时间驱动办公动作，接入侧不能继续把它当作纯静态 working 姿态无限复用。若 Codex 做缓存，需要覆盖 `activity/support/time/deskHeight/deskFrontZ` 等表现输入，并重新验证实际整局性能；缓存与优化由 Codex 负责。

## 7. Codex 联合验收与未验项

1. 在接入层为每个需要新语义的 `CharacterVisual` 持有一个 motion 实例，以 `motion.update()` 替代对应的原 `visual.update()`；保留既有普通路径与资源销毁顺序。
2. 绑定一把真实办公椅和一张真实升高桌，验证桌高、桌面前缘、角色根位置、重复椅隐藏、手上接触和脚底支撑；本批预览桌不是主场景实体验收。

4. 由 Codex 接入巡逻、停步检查、快速奔跑和扫视语义，验收实际移动中的滑步、速度、视野、触发、追踪、抓捕与暗室规则。本批没有实现这些逻辑。
5. 主场景真实顶板、低顶房间碰撞、背锅通行、九角色整合性能、连续有效游玩和公开发布均未由本补丁验收。
6. 本批只做单人表现，不涉及联网、音频、手机或加载页改动。
