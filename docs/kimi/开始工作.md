## 固定UI接口

```ts
import type { UIModel, UICommand } from '../contracts/game';
import './theme.css';

export function createUI(
  root: HTMLElement,
  onCommand: (command: UICommand) => void,
): {
  render(model: UIModel): void;
  destroy(): void;
}
```

UI只读模型；按钮只发契约中已有命令，不另存真实局时/胜负/规则。Codex负责绑定、鼠标锁定、键盘、暂停、加载和游戏事实。render会频繁调用，页面切换可重建，HUD请局部更新文本/属性，避免每帧重建全DOM、丢焦点或打断设置滑块。用textContent或可靠转义处理文本，不把错误信息直接插HTML。

模型单位：`remaining`/`elapsed`/`warning.remaining`/`protection`都是秒；`stamina`为0—4秒；`interaction.progress`由绑定映射为0—1。`clock`是18:00等世界时间文案。message/bubble生命周期已由Codex决定，UI不自定时。`preview`为true时标小型“展示样例”，不冒充真实游戏。

## 页面与样式要求

- 首页：游戏菜单而非营销页；“开始上班”“怎么玩”“设置”，禁用“多人模式 · 待开发”，小型鸣谢/版本。背景复用Codex渲染的真实Three办公室。
- 三页教程：移动/跑蹲跳/装忙、预警与空间规则、打卡/暗室/锅/滚椅；可翻页返回，不启动真实局时。
- 设置：quality、sensitivity、invertY、reducedMotion、textScale；不添加未接通的假设置。
- loading真实阶段文案、ready“开始这一局”、error重试/回首页。
- playing HUD：左上时间/打卡/目标，上中三秒宣告，右上透明规则，底部当前交互；状态包括装忙、暗室、背锅/手持锅、粘椅、拖回、瞄准领导会被炒。
- phone规则记录：不暴露未知领导坐标或完整地图，查看不暂停；close-phone命令关闭。
- 暂停：继续、设置、同种子重玩、回首页。
- 结算：正常下班、超时加班、被炒特殊结局分清；同种子/新办公室/回首页。

`#scene`固定全屏；`#ui`/UI外层pointer-events:none，仅真实按钮和模态交互区域pointer-events:auto，游戏HUD不挡鼠标。1366×768和1920×1080可读，中文长文案不遮路。清楚文字+形状，不只依赖颜色。减弱动效遵守设置与prefers-reduced-motion。

视觉由你制定统一方向：正常办公室与黑话成为真实物体的荒诞反差，人物认真、轮廓清楚。角色/锅/椅/灯/打卡机在暗处可辨；不要连续闪屏、重模糊或大遮罩。绿色/奶白/克制橙提示只是Codex建议，非既定Kimi设计。
