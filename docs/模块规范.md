# 本工程的制作与模块规范

来源：工作区通用规范，2026-10-30按V3与最新职责纠正更新。新制作会话已启动，本文不推断代码、资产或隔离验证的实时状态。游戏规则以[单人完整玩法V3](单人完整玩法提案-v3.md)为准；取消工时与电脑任务，状态包含打卡、出口、锅归属、椅、追责、冲刺和局时。

**最新分工优先：Kimi Work独立负责全部UI视觉、角色/道具/场景外观、模型、动画表现和美术监督，并独占Tripo资产设计与生成；Codex负责内在玩法、地图逻辑、移动/镜头程序、UI绑定、测试、集成和发布。** 用户已澄清“手感”是“手板”的语音错误，指UI与建模，不移交操控程序。详见[视觉职责补充](../CODEX_VISUAL_REFERENCE_ADDENDUM.md)。

## 1. 文件所有权与状态

| 模块 | 所有者 | 边界 |
| --- | --- | --- |
| contracts | Codex协调 | 简单状态、命令、事件、资源ID；不依赖引擎或服务SDK |
| rules | Codex | 唯一局时、目标、胜负、指令与状态效果，不放模型路径和样式 |
| world/gameplay | Codex | 房型/模板/地图、碰撞、导航、输入、镜头、程序对手、规则适配与整体游玩测试 |
| ui/theme、ui/views | Kimi | 主题、布局、字体、组件、表现动效；只读数据，输出语义命令 |
| ui/bindings、app | Codex | 状态映射、按钮命令、流程、暂停、装配和资源接入 |
| presentation | Kimi Work | 全部角色/道具/场景外观、模型、动画、灯光、视觉反馈与美术监督；不设计机制/房型，不自改规则，不承担完整游玩测试 |
| assets/source、assets/runtime | Kimi Work制作并交付；Codex接入 | 原始文件与运行导出分开；Kimi独立设计、生成和处理，Codex维护集中资源映射并记录集成结果 |

并行前给每位执行者列出可写文件范围。不要互相覆盖，也不要全员都改装配入口。需要改契约时由Codex协调，再同步样例与正式绑定。Codex仅可制作规则、空间和操控验证所需的最小灰盒，不替代或预定视觉成品；Kimi未就绪时，Codex继续内在程序，不自行补做UI、建模或Tripo生成。

双方可只读学习 `/Users/yb/Desktop/Name/Zcode/设计/Kimi提示词库`。Kimi自己选参考并独立决定风格；用户认可办公室案例逼真，不构成照搬要求。Codex提供可测的技术约束，不能把灰盒样式或技术选型变成美术定稿。

## 2. UI

主题、展示、绑定分文件。开始按钮只发StartGame之类语义命令，由应用生成地图与启动规则；视觉组件不能另建真实计时器或直接改胜负。

使用原生可交互按钮和文字，不能用整页图片替代UI。正常、加载、错误、禁用、长文案、胜负、暂停状态均用固定样例可独立预览；明确样例是展示数据，不冒充正在运行的游戏。

预览复用正式组件。规则提示与角色气泡分开，气泡冷却不能吞掉领导宣告。焦点、键盘、鼠标锁定和Esc行为由绑定协调，不能点击按钮又甩出锅。

## 3. 角色与场景

控制/碰撞根节点由玩法持有，视觉模型挂独立子节点；替换外观不得改移动事实。动画使用走路、坐姿、打字、背锅、滚椅等语义状态，不在业务中依赖深层美术节点名。

资产必须标明单位、尺寸、朝向、原点、骨架、动画列表、背锅/座位/手部挂点、贴图与版本。静态模型、骨骼绑定、可播放动画和坐姿不穿模是不同验收项。

网格与碰撞分开，渲染/导航/可交互范围必须同源。变透明不等于可穿，饼变大后不能视觉变大而碰撞不变；材质、尺寸、遮挡、骨架或根运动一旦影响玩法需专项验证。

本版没有声音感知或听觉必需提示；所有关键状态须静音可读。

## 4. 服务与工具

本版单机核心无需后端或运行时LLM。Kimi/Tripo用于制作，不要求玩家游戏时联网生成。确需秘密凭据的服务通过本地开发代理或后端访问，不将密钥打入前端。

Tripo官方CLI/API的资产设计、提交生成与后续处理只由Kimi执行；此前双方可调用与Codex代执行条款撤回。已提交任务只按明确ID/状态登记，保留结果交Kimi判断，不盲目取消或重复生成，本次文档修正不接管运行进程。接入成功、已登录、有可用额度、生成成功、文件可加载、已集成、已审美验收分别记录；占位不能冒称Tripo生成，其他模型不能冒称Kimi。余额与仓库空状态的旧查询仅是快照，以实时记录为准。

## 5. 独立预览与交付

UI、角色、场景分别有独立预览入口，README写明实际启动方法；不要仅列计划中的未实现路由。每45—60分钟集成一个可操作小结果，并在同一状态拍图复核。

验收按改动范围选择有意义的自动检查与人工操作。只换样式无需全量游戏测试；涉及碰撞、视线、输入、规则或状态必须验证真实链路。提交时列源码/资产、启动方法、实际测试、审美复核、仍为占位及未完成项。

最终记录应区分：策划已写、模块已实现、预览可用、实际试玩通过、Kimi已审核、已公开发布。这些不能互相替代。
