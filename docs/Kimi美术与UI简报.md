# 《领导说的都是真的》Kimi 美术与 UI 简报

更新：2026-10-30。当前交付为完整设计稿，不代表已调用Kimi、Tripo、生成模型或完成游戏。玩法唯一依据为[单人完整玩法提案v3](单人完整玩法提案-v3.md)；本简报定义外观职责及交接，不另写一套规则。最新用户要求优先于归档版本。

## 1. 作品与职责

作品是电脑浏览器里的第三人称职场规则怪谈：已经到18:00，员工想打卡、探索出口并下班，领导说出的黑话会真实改变世界。首版仅单人一局式逃离，可重玩同一种子。取消工时、电脑交付任务和办公小游戏，电脑用于开场豆包彩蛋及假装工作。无听觉机制，静音时必须理解全部关键状态。

| 责任 | Kimi | Codex |
| --- | --- | --- |
| UI | 主题、排版、字体、图标、可编辑展示组件、界面动效、独立样例预览 | 唯一状态、语义命令、绑定、焦点与输入、计时和真实数据 |
| 角色与物件 | 外形、材质、服装、轮廓、骨骼姿态、表情和展示动画；可为分配资产调用Tripo | 移动、碰撞、命中、拿取/投掷、挂点状态、抓捕、惩罚、动画驱动 |
| 办公室 | 为指定尺寸和模块提供墙面、家具、灯具及装饰外观 | 房间种类、模块模板、门与通路位置、随机生成、导航、灯光与视线的玩法判定 |
| 检查 | 首轮首页/HUD视觉方向；最终真实截图和录屏的外观、可读性与穿模评审 | 整体游玩测试、规则正确性、通关、公平性、反固定打法、输入手感、性能、发布 |

**Kimi不负责设计游戏机制、房型模板、关卡连接、难度或胜负，也不承担整体游玩测试。** Kimi可提出视觉问题，不能通过改移动速度、碰撞尺寸、目标数量或指令时机自行修玩法。最新由Kimi Work独立负责视觉设计、制作与Tripo资产生成，Codex只负责内在程序和接入；旧双方生成与Codex代生成安排已撤回。分工与实际调用方法见[工具与资产调用](工具与资产调用.md)。

本项目由用户一人依靠AI制作，无真人队友，制作预算约六小时。Kimi与Codex是明确分工的制作工具，不按多名真人的稳定产能估算。

## 2. 视觉设计权与参考授权

用户将完整视觉设计、制作与监督交给Kimi Work。Kimi根据项目理解自行决定视觉风格、模型造型、配色、字体、材质、灯光表现与动作语言；Codex提供功能/技术接口和必要约束，不先替Kimi定风格、做完界面模型再交其换皮。用户已澄清“手感”为“手板”，此次纠正的是UI与建模的包办，移动/镜头程序仍由Codex负责。

用户明确允许只读研究 `/Users/yb/Desktop/Name/Zcode/设计/Kimi提示词库`，范围限该库及条目指向的公开预览。Kimi自行选择适合本项目的参考，提示词须配套查看效果图，网页参考应实际体验预览或说明未能体验的部分。用户满意办公室案例的逼真与完成度，但未指定采用其整套样式；不能将这个认可扩写为某一种固定美术风格，也不排斥恰当借鉴。

项目核心为一本正经的人物与荒诞规则后果之间的反差。首页作为游戏入口、近第三人称、关键信息静音可读和不遮挡操作属于项目要求；具体视觉解决方式由Kimi设计。已由Codex产生的视觉成果先保留并交Kimi判断采用、调整或替换，不作为默认美术定稿。具体交接见[最新补充指令](../CODEX_VISUAL_REFERENCE_ADDENDUM.md)。

## 3. 全部页面与状态

| 界面 | 必须出现的内容 | 行为边界 |
| --- | --- | --- |
| 首页 | 标题、开始上班、教程、设置、多人模式待开发、鸣谢 | 多人入口禁用并明确标注，不连接假大厅；本版没有继续存档按钮 |
| 教程 | 三页图文：移动/跑蹲跳与交互；领导预警/装忙/规则后果；打卡离场/甩锅与滚椅 | 可翻页、跳过和返回；不另做教学关，不启动正式局时 |
| 设置 | 实际支持的画质、鼠标灵敏度、文字尺寸、减弱非必要动效 | 展示与修改实际配置，未接通项不做可用假按钮 |
| 本局加载 | 真实下载进度、模型与动作准备、场景准备、失败原因和重试 | 轻量首页先出现；开始后加载本局必需资源；准备完成才允许进入并启动计时 |
| 开场电脑 | 员工坐本人椅子，屏幕打开本地预写豆包对话；能看到18:00 | 文案使用v3主方案；E可离座，不强迫等彩蛋逐字播放，不接真实豆包服务 |
| 游戏HUD | 剩余时间、打卡状态、离场目标；当前领导规则、交互提示和角色状态 | 不显示工时、文件提交或劳动进度；目标数量与状态只读主规则 |
| 装忙状态 | 假敲键盘/动鼠标、E离座提示，保留周边环境视野 | 不是电脑小游戏，不增加任务进度；领导如何反应由Codex规则决定 |
| 规则宣告 | 中上醒目原话、目标物或对象、三秒预警 | 不夺取鼠标或移动控制；预警结束的生效由主规则判定 |
| 透明规则栏 | 生效中的原话、目标、直白后果、剩余时间或结束条件 | 推荐右上；允许Kimi依真实画面微调；不隐藏长期粘椅状态，不自推规则并发数 |
| 瞄准与持锅 | RMB瞄准、LMB投掷、Q切换手持与背/头挂载的可用提示 | 领导是瞄准目标时明确提示“甩给领导：会被炒鱿鱼”；不把风险藏在教程深处 |
| 被拖回 | 领导动作、角色反应、清楚的快速回工位过程 | 按主规则2—4秒完成；不为过场额外延长失控时间 |
| 粘椅状态 | 坐姿、轮子运动、不能蹲跳的简短反馈；锅从背部转到头顶 | 本局永久粘椅；UI不画倒计时或恢复按钮，不暗示能自行起身 |
| 手机/规则记录 | 已读命令、规则原文与玩家实际知道的信息 | 不显示未见领导的实时坐标，不生成全图路线或额外任务；打开是否暂停由主方案决定 |
| 暂停与恢复 | 暂停原因、继续、设置、重开、回首页 | 时间和所有效果是否暂停由统一状态控制，返回后恢复正确输入焦点 |
| 正常下班结算 | 主规则给出的正常离场结果、用时、种子 | 同种子重玩、新种子重玩、回首页 |
| 加班失败结算 | 超时与未离场事实、种子 | 不伪造未发生的统计；直接提供重玩 |
| 被炒鱿鱼结算 | 清楚标为特殊结局，呈现“提前下班了——被炒鱿鱼”这一反差 | 仅响应主规则的fired结果，不自行当成正常下班胜利 |
| 错误与兼容提示 | 加载失败、图形能力不支持、运行错误的具体可行操作 | 可重试或返回首页；优先电脑键鼠，不承诺触屏版 |

豆包对话是游戏内预写的虚构彩蛋。采用Codex核对后给出的完整文案；Kimi不补造“官方原话”、外部链接或真实账号内容，不接嵌入网页或运行时AI调用。

## 4. HUD与信息组织

- 剩余局时、打卡与离场目标需要清楚可见，位置与排版由Kimi设计。
- 中上：领导三秒预警原话与作用目标，最多两行可读大字；详细内容在规则记录保留。三秒后大字收起，仍生效的后果继续可查。
- 透明当前规则栏保留有效后果；位置、样式与可读性方案由Kimi设计，右上不再作为指定位置。
- 当前可操作提示的位置由Kimi设计。拿锅/持锅/装忙/坐椅状态改变时及时换文案，避免同时列出当前不能执行的动作。
- 角色附近：抱怨气泡约五秒显示、消失后约三十秒冷却，具体触发与计时由状态提供；不能挡住瞄准或吞掉领导宣告。
- 举报、被看见和风险提示只展示主规则允许玩家知道的状态。未知敌情不作为视觉装饰泄露。
- 鼠标锁定、Esc和手机/菜单输入焦点由Codex统一处理；UI动画不能阻止离座、暂停或取消瞄准。
- 检查1366×768和1920×1080，覆盖浏览器缩放、长中文、多条状态、暗室、坐椅及手持锅。文字/按钮保持真实可编辑、可交互元素。

## 5. 动作与滑稽感的表现规格

下表时长是**外观初值建议**，用于安排动作节奏，不新增玩法锁定。碰撞、投掷释放、挂载、抓捕和输入生效点均由Codex主状态控制；Kimi可以调整姿态曲线和混合，不能改规则事件发生时间。

| 动作 | 外观节奏建议 | 中断、挂点与交接 |
| --- | --- | --- |
| 待机、走、跑 | 共用骨架循环；转身带轻微上身滞后，停步不过度滑行 | 移动根由Codex控制；短混合约0.10—0.15秒，不以根动画拖动碰撞体 |
| 下蹲/起身 | 约0.18—0.25秒，收肩弯膝，头部保持可读 | 主状态先确定是否允许；粘椅时不播放假下蹲；净空由碰撞处理 |
| 跳与落地 | 起跳预备约0.10秒，落地回弹约0.15秒 | 真正离地和着地由运动状态驱动；不为了蓄力动画延迟输入 |
| 装忙 | 短打字循环、鼠标小移动、偶尔抬眼，避免疯狂甩手 | 手靠近键盘/鼠标锚点；离座立即响应，循环可在任意位置混出 |
| 拿取小物件 | 伸手约0.15—0.25秒，物件贴合手部后收回 | 右手持物挂点；实际拾取成功后才显示持有，失败不凭空出现 |
| Q拿锅/收锅 | 拿锅时微微侧身，站姿从背后拿，坐姿从头顶取；整体约0.3—0.45秒 | 背、头、手三个挂点由状态切换；一次只显示一口锅，不跨状态复制 |
| 瞄准 | 上身侧转、手腕稳住，眼神跟随目标 | 可边走边瞄；肩部姿态不强迫摄像机抖动；取消后迅速回原姿态 |
| 甩锅 | 小幅蓄势—挥手—回收，总约0.4—0.6秒；夸张重心但保持方向清楚 | 投掷事件由Codex触发，抛物线由玩法计算；回收可被下一次合法操作混出 |
| 锅命中 | 锅轻颤约0.15—0.25秒，被命中者短暂耸肩/回头 | 是否命中和吸附由规则给出；不可用动画碰撞自行转移归属 |
| 背锅/顶锅 | 站姿略含胸，坐姿头顶保持锅轮廓；随移动少量摆动 | 摆动不改变真实体积与速度，不遮住第三人称前方路线 |
| 领导拖回 | 伸手抓领/袖—员工脚步滑移—迅速回工位落座 | 总过程遵守主规则2—4秒；抓握挂点、拖拽轨迹由Codex提供，不穿墙直线拉人 |
| 粘椅 | 落座轻回弹，起身意图被粘回的滑稽反应只作短表现 | 椅子座位锚点保持骨盆稳定；本局无法站起，禁止播放成功离椅动作 |
| 滚椅移动 | 双脚蹬地、转向时肩膀倾斜、轮子按实际位移滚动 | 身体和轮子表现跟随玩法运动，不能反向驱动速度；滑行要看得出方向 |
| 同事仇视/举报 | 停手、侧目、瞥向玩家、拿手机；姿态变化克制清楚 | 同事仍留工位；目击、仇视和举报时间由主规则提供，不因动画结束自动发报告 |
| 结算反应 | 正常离场松口气；超时僵住；被炒鱿鱼先松气再反应过来 | 结局已由主规则确定，动作不新增胜负；允许跳过表现并重玩 |

角色骨架语义至少覆盖头、躯干、左右手、骨盆和脚。额外挂点：手持物、背锅、顶锅、座椅骨盆锚点、领导抓握点。锅与椅子独立资产，不焊死在人物网格里。

## 6. 模型与场景外观交接

Kimi可调用Tripo生成分配给自己的角色或物件，也可用程序几何制作可控外观。家具运动需要的分件、米制尺寸、正面方向、轴心、挂点及碰撞包络由Codex先给出；房间模板与连通性不交给生成模型决定。

每项资产交付稳定ID、版本、来源、原始文件、运行文件、尺寸、朝向、轴心、材质槽、骨架、动画和挂点说明。GLB/glTF作为网页运行交付方向，实际导出需加载验证；静态网格不等于有骨骼、有动画或可直接坐椅。

完整随机办公室不交给Tripo整图生成。墙、门、隔断与机关继续采用Codex可控结构，Kimi设计其表面与外观；美术更换不能偷偷改变通路、遮挡与交互距离。

## 7. 可编辑交付和预览

Kimi拥有约定的主题、界面展示和分配的角色/场景表现文件；Codex拥有契约、绑定与装配入口。每次并行任务明确文件范围，不覆盖他人改动。

交付内容：主题变量、可编辑UI组件、必要图标与纹理、固定状态样例、独立UI预览、分配的角色/物件预览、资产记录和外观待修项。UI样例复用将进入游戏的真实组件，不只交截图。

只读输入包括页面状态、剩余时间、打卡/离场状态、宣告、当前规则、角色姿态、锅持有/挂载、瞄准风险、可用操作与结局。操作输出只发语义命令，如开始、教程翻页、设置、交互、切换持锅、投掷、暂停、同种子/新种子重玩。UI不保存另一份真实计时或胜负，不内嵌API密钥。

预览覆盖：首页、多人待开发、教程三页、加载/失败、18:00开场、装忙、未打卡/已打卡、三秒预警、背锅/头顶锅/手持锅、瞄准领导风险、拖回、永久粘椅、暗室、暂停、正常下班、超时、被炒鱿鱼。预览数据标在预览工具里，不作为正式游戏文案。

## 8. 两轮外观评审与验收边界

第一轮：Kimi交首页、HUD和代表性角色/物件方向，明确文字层级、人物轮廓和滑稽动作语言。Codex检查接口与资源能否接入。

第二轮：Codex提供实际游戏截图和短录屏，覆盖装忙、领导预警、甩锅、拖回、顶锅滚椅、暗室、打卡/离场与三种结局。Kimi只评外观统一、可读性、穿模和表现节奏，给具体修正；Codex负责实操、规则、可通关、输入、帧率与部署验收。

六小时内优先清楚反馈、自然姿态和统一风格。共用角色骨架、家具材质和动作层；不做大量独有骨架或长过场。正式公开版的性能由Codex按[上线与流畅度验收](上线与流畅度验收.md)测量，不能以Kimi看过截图代替通过。

每次交付分别记录设计完成、独立预览可用、已接入、外观评审完成和Codex实际验收状态。当前均为制作前规格，未宣称这些工作已经完成。
