## 2. 选用方式：本地CLI驱动Tripo云端生成

Kimi Work选择视觉方案、编写资产提示词、调用Tripo官方CLI/API、跟踪任务、下载与处理模型，并交付可用资产。Codex提供尺寸、挂点、碰撞与性能约束，接收Kimi交付后检查技术规格并导入网页工程。Kimi通道或工具未就绪时，记录具体缺口，由Kimi继续处理或请用户解决；Codex不能因此代做UI、建模或提交Tripo任务。

Codex可用最小灰盒验证空间、操控与规则，但灰盒不能替代或预定视觉成品。双方获准只读学习 `/Users/yb/Desktop/Name/Zcode/设计/Kimi提示词库`；由Kimi自己选择参考并独立决定视觉风格。用户认可办公室案例的逼真效果，不等于指定照搬该案例或固定画风。

生成接口不向玩家浏览器开放。玩家只下载已完成的模型与游戏代码，游玩时不依赖Tripo、Kimi或豆包在线生成。

官方CLI支持生成、处理、下载、预览以及输出目录管理；格式转换、骨骼绑定等步骤也可能计费。正式执行前按当前版本的内置文档选择参数，不因为历史例子存在就套旧模型版本。[Tripo CLI官方说明](https://developers.tripo3d.ai/en/docs/cli)

## 4. 防止重复生成的资产登记

Kimi维护生成与外观记录，Codex维护接收与集成记录，共用唯一资产清单。每项记录：资产ID、用途、尺寸/朝向/分件、所有者、提示词或参考图版本、Tripo任务ID、状态、原始目录、运行目录、实际积分和验收结果。

生产规则：

1. 生成前核对唯一资产ID和文件所有权；新Tripo任务只由Kimi提交，Codex不再提交生成任务。
2. 先检查现有版本与任务记录；可复用的模型通过服装、材质、尺度或姿态变化复用。
3. 提交后立即记任务ID。超时或网络中断先查询该任务，不用重新生成作为普通重试。
4. 已提交任务先登记明确ID与状态，保留现有结果交Kimi判断；不因分工修正盲目取消、丢弃或重复生成，也不由本次文档会话接管运行进程。Kimi按原任务继续后续处理。
5. Kimi检查预览与真实网格并交付运行版本，不只看缩略图就算资产可用；Codex检查技术规格后接入。外观与技术验收分别记录。

原始文件按`assets/source/tripo/<asset-id>/<version>/`保存；运行资产进入统一映射目录。以上是目录规格，是否已有实际文件以制作记录为准。不要并行使用含糊的“最新任务”作为另一代理的输入，交接使用明确任务ID和路径。

## 5. Kimi生成与Codex接入步骤

- Kimi读当前执行环境的CLI内置命令说明，先用不创建任务的预览计划检查所选模型与可用估价；估价不是最终账单。
- Kimi独立确定美术方向，在网页实时运行预算内提交模型需求、等待任务并保存输出。面数、贴图与加载成本需实测；技术预算不自动等于低多边形画风，也不能由Codex先替Kimi定风格。
- 先验人物和核心物件的尺寸、朝向、轮廓、贴图、材质槽与分件；需要骨骼的人物先做兼容检查，再绑定和重定向动作。
- 原始结果保留；另做网页运行版，检查GLB/glTF实际加载、贴图路径、透明材质、骨骼与动画。
- 在角色/物件预览中确认挂点、动作与相机可读性，再进入完整游戏。碰撞体、质量、导航和规则不从视觉模型自动推断。
- 记录实际任务费用、生成时间及失败原因；没有账户和真实任务数据时，不承诺精确费用或几分钟必出可用模型。

官方恢复原则：任务等待超时可能仍会成功并计费，应继续观察原任务；网络错误导致提交结果不明时，先核对任务再重交。[CLI任务与恢复说明](https://developers.tripo3d.ai/en/docs/cli)

## 6. 资产优先级

| 顺序 | 资产 | 使用与复用 |
| --- | --- | --- |
| 首批 | 统一员工基模 | 主角与同事优先共享骨架和基础动作，服装/发型/材质区分 |
| 首批 | 领导外观 | 轮廓易辨，优先适配已有骨架；需要独立生成时使用明确尺寸合同 |
| 首批 | 实体锅 | 手持、背挂、头顶和飞行共用一件资产；锅柄方向和挂点稳定 |
| 首批 | 办公滚椅 | 座面、轮子等按表现需要分件；角色与椅子不生成成焊死的一体 |
| 首批 | 饼与工位部件 | 饼需可推、可缩放的稳定轮廓；桌、电脑、椅子分开 |
| 后续 | 少量办公装饰与外观变体 | 仅在核心交互和加载预算允许时扩充，复用材质和实例 |

这张表规定制作顺序，不限制用户已授权的合理生成数量。需要重做外观时由Kimi按资产记录提出明确修正，避免无目标反复生成。墙、门、隔断和打卡机的逻辑位置、碰撞/交互范围及随机房间连接由Codex设计和控制；它们的外观、模型与表现由Kimi制作，不让Tripo整图生成决定关卡。

## 7. 模型不等于动作

Tripo提供骨骼兼容检查、自动绑定与动画重定向，兼容性必须先检查；获得静态网格不等于获得正确坐姿或自定义动作。[骨骼检查](https://developers.tripo3d.ai/en/docs/animations-rig-check)、[自动绑定](https://developers.tripo3d.ai/en/docs/animations-rig)、[动作重定向](https://developers.tripo3d.ai/en/docs/animations-retarget)

走、跑、蹲、跳可优先复用统一骨架的基础动作；装忙、取锅、瞄准、甩锅、拖回、粘椅和头顶锅需要骨骼姿态、挂点与程序过渡结合。锅的飞行/吸附、椅子的真实运动、饼膨胀与桌升高由Codex规则和引擎适配控制。Kimi独立负责全部动作形象、动画制作与表现节奏；Codex通过约定语义状态驱动，不能把动画结束当作命中、抓捕或通关事实。

完整表现规格见[Kimi简报](Kimi美术与UI简报.md)。不承诺Tripo一次生成所有滑稽动作，也不把模型生成完成标成动画或游戏完成。
