# 18:00 离岗现场 · 视觉设计说明

## 一、实际看到的问题

本诊断基于本次实际打开并截图查看的当前首页、加载页、办公室与正式角色预览；未把未查看的内容写成评审结论。

- **首页与加载页像两套产品。** 首页是暗色办公室里的纸质通知，加载页突然变为纸白技术校准面板，色彩、人物叙事和信息组织缺少承接。
- **暗背景削弱了真实人物。** 当前办公室背景中人物较小、面部与姿态不突出，首页没有充分利用已经完成的员工与领导资产。
- **纸张通知与现场相互分离。** 标题、按钮和背景各自成立，但“领导发言改变现实”的冲突没有成为一个主画面。
- **加载图形完整但偏通用。** 锅、椅与 18:00 被放在空旷的校准构图里，更像技术展示，缺少员工正在逃离的紧迫与滑稽。
- **手机主要是纵列缩放。** 旧加载页把三个符号依次排开，主视觉焦点弱；新设计需要分别处理竖屏与横屏，而非只缩字号。

现状证据保留在 `audit/`。这些是视觉问题，不是对玩法、性能或程序正确性的判断。

## 二、三个构图方向

1. **离岗现场（已采用）**：左侧标题与操作，右侧是领导、实体锅和带椅撤离的员工。加载时保留同一舞台与线场，只切换左侧内容。最直接表达“一本正经的职场荒诞”。
2. **制度叠印**：超大标题、18:00 时间戳与竖线人物轮廓组成内部通告。平面表现更强，但真实人物叙事较弱。
3. **办公室逃生图**：工位、锅椅与出口形成图纸路线网络。空间感更强，但容易像企业后台或关卡编辑器。

选择第一方向的原因：玩家无需阅读机制列表，就能从一个场面理解人物、规则和逃离目标；首页与加载页也能自然共享同一视觉资产与状态连续性。

## 三、统一视觉语言

### 色彩

| 角色 | 数值 | 用途 |
| --- | --- | --- |
| 纸白 | `#fafaf8` | 页面、文字操作区、对话框 |
| 浅灰 | `#eeeeeb` | 离岗现场、次级表面 |
| 钴蓝 | `#2152e7` | 主按钮、当前阶段、焦点、制度标记 |
| 近黑 | `#111212` | 标题、正文、边框 |
| 灰阶辅助 | `#696b68`、`#d3d4ce` | 辅助文字与分隔线，均由核心灰阶延展 |

没有蓝紫渐变、玻璃态、模糊或大阴影。主按钮悬停转为近黑；错误通过文字、边框与状态结构表达，不靠恐怖红色氛围。

### 字体

不下载外部字体，避免字体阻塞开场。

- 标题：`Songti SC / STSong / Noto Serif CJK SC / Source Han Serif SC / Georgia / serif`，中文衬线优先，字重 600，不使用中文伪斜体。
- 界面：系统无衬线栈，显式包含 `PingFang SC`、`Microsoft YaHei` 等中文字体。
- 坐标、件数、编号：`ui-monospace / SFMono-Regular / Menlo / Consolas / monospace`。

### 形状与间距

- 主面板、话术与对话框：17px 圆角；按钮使用 10—12px 的次级圆角。
- 主边框 1px；不使用卡片套卡片；用分隔线、留白与字号组织信息。
- 桌面页面外边距 28px，顶栏 76px，底栏 42px。
- 桌面内容区采用不对称双栏，现场略宽于文字区；标题按视口 57—88px 缩放。
- 手机页面外边距 11px，内容左右 22px；主要按钮高 52px，所有可见操作目标至少 44px。
- 焦点：2px 钴蓝轮廓，4px 偏移；不删除系统键盘焦点。

### 按钮状态

| 状态 | 表现 |
| --- | --- |
| 主按钮默认 | 钴蓝底、纸白字、双向信息“动作 + ↗” |
| 次按钮默认 | 透明底、近黑边框与文字 |
| 悬停 | 主按钮转近黑；次按钮出现浅灰底与钴蓝边框 |
| 按下 | 仅 1px 位移；减少动态效果时取消 |
| 禁用 | 浅灰底、灰字，保留原因文案；进入按钮不会伪装可点 |
| 键盘聚焦 | 钴蓝外轮廓，和悬停无关 |
| 失败重试 | 独立钴蓝描边按钮，按真实资源 ID 触发 |

## 四、主视觉与资产

主视觉直接来自项目现有运行资产：`employee-base-v1`、`leader-v1`、`chair-v1`、`pot-v1`。没有重新发明人物、改变服装或用其他角色替代。

- 员工使用正式组件的滚椅姿态；领导使用站立发言姿态；锅为独立真实道具。
- 渲染脚本保留人物比例与资产 ID，诊断在 `audit/render-diagnostics.json`。
- 首页运行图 `assets/entry-scene.webp` 为 1500×1200 透明 WebP，约 40 KB；不会在首页再次初始化 Three.js。
- 领导话术、18:00、工位标注和全部按钮仍是 HTML 文本，不烘焙进图片。

## 五、预加载到首页的连续性

- 首次打开默认进入资源加载页，人物舞台、18:00 Canvas、公司名与顶栏在后续首页继续保持。
- 只有真实 `ready` 且没有失败项时才开放“进入首页”；公司标识与教程不能绕过加载门槛。
- 首页“开始上班”在资源已就绪的前提下直接触发开局，不再进入加载页。
- 加载到首页不重新创建线场实例，因此不会重新采样。
- 没有持续 3D 特效、自动轮播或无意义入场动效；主要持续运动只来自规范线场。

## 六、桌面与手机分别构图

- **桌面横屏**：左侧标题与操作，右侧完整离岗现场；五阶段为纵向真实状态列表。
- **手机竖屏**：先展示约 180—290px 高的现场，再展示标题、状态与操作；加载话术移至右侧，避免遮住领导面部。360×740 使用更紧凑的舞台与阶段间距，进入与重试保持首屏可达。
- **手机横屏**：紧凑双栏；加载标题变为一行，五阶段改为横向阶段轨。844×390 与 740×360 均检查主要动作不被遮挡。
- 长失败信息允许页面自然滚动，不通过裁切隐藏错误；主要动作仍在首屏。

## 七、教程与实际操作

| 教程页 | 对应实际操作 |
| --- | --- |
| 移动与交互 | WASD、鼠标、Shift、C/Ctrl、Space、E、F、Esc；粘椅后不能蹲跳，但可继续滚椅移动 |
| 规则与道具 | Q 取锅/归位、右键瞄准、左键投出、R 轻放、甩给领导的特殊结局、暗室保护 |

手机长教程保留滚动与翻页按钮可达；不以缩短文案为由删掉实际操作。

## 八、量化线场规范继承

`src/line-field.ts` 直接复用项目现有 `canvas-view.ts`、`field.ts` 与原创 18:00 `symbols.ts`，本目录没有重写算法或修改参数：

- 单次 300×300 源画布、5×5 Rec.709 平均亮度、60×60 `Float32Array`。
- 60 列 30 段、0.7px 段间隙、四档竹节线宽与透明度、固定 7319 噪声。
- 指针累计位移、触控与键盘聚焦反馈；数值亮区扫描框来自亮度投影，不是 AI 识别。
- resize 只调整显示与 DPR，不重新读取源像素；动画中不读取源像素。
- 暂停、后台、不可见、离屏、来源弹窗及 reduced-motion 停止装饰循环；资源更新不被暂停。
- 销毁取消 RAF、监听与观察器。

独立验证覆盖单次采样、resize 不重采样、扫描目标、触控、键盘、弹窗和暂停后的真实状态更新。
